## My draft pipeline (attack this)
1. Studio instance: copy data/pglite to a scratch dir, run core with PORT=8797 PGLITE_DIR=<copy> RENDER_CACHE_DIR=<scratch>, run web on :3011 pointing CORE_API_URL at it. Prefer a production build of apps/web to remove the DEV model chip and the Next dev indicator (note next.config.ts has `output: "standalone"`, `cacheComponents: true`); fallback is `next dev` plus injected CSS hiding dev UI. Take DB checkpoints (copy the PGlite dir while the core is stopped) before each agent turn so a bad take can be rolled back.
2. Capture: Playwright page, CSS viewport 1440x810, deviceScaleFactor 2 (2880x1620) or 2.667 (3840x2160); CDP `Page.startScreencast` (jpeg q~92, everyNthFrame 1) with each frame's metadata.timestamp, frames piped/encoded with ffmpeg to H.264 CRF ~14 with keyframes every 0.5 s, then conformed to constant 60 fps. Fallback if effective fps < 24: headed Chrome window + ffmpeg avfoundation display capture at 60 fps, cropped.
3. Event log on the same clock as frames: every scripted action writes {t, type: move|click|type|waitStart|waitEnd|mark, x, y, box} (boxes from locator.boundingBox()). The real Playwright mouse is moved along the same eased path in real time so hover states in the footage match. A one-frame full-screen colour "sync flash" at take start/end verifies the frame clock against the event clock.
4. No cursor is baked into footage. An SVG cursor, click feedback, camera keyframes (scale/x/y on a wrapper around the <video>), highlight boxes and caption timings are all GENERATED by a build script from (events.json + an edit decision list mapping source time to film time, with agent waits compressed by ffmpeg setpts into short time-lapses) into HyperFrames scene files. Captions and SFX are anchored to events, not typed-in seconds.
5. One sub-composition per scene, each with its own pre-cut clip; root holds scene hosts, one captions host, music and SFX <audio>. Render 1920x1080 at 60 fps, `--video-frame-format png` or jpeg depending on disk.
6. Waiting for the agent: wait for the "Stop generating" button to appear, then disappear, then for the "Suggested changes" list; per-turn timeout 6 min; retake from checkpoint on failure.
